# Лабораторная работа №4: Базовые растровые алгоритмы

Дисциплина: **Программирование компьютерной графики**

Вариант: **№1** (*Базовые алгоритмы растеризации отрезков и кривых*)

Интерактивное настольное приложение на базе GUI Tkinter для визуализации, анализа и стресс-тестирования алгоритмов растеризации отрезков, окружностей, сглаженных линий и кривых второго порядка на двумерной пиксельной сетке.

## 📌 Описание и возможности

Приложение реализует трехслойную модульную архитектуру, четко разделяющую математические расчеты растрового движка от GUI-интерфейса.

### Основные функции:

* **Интерактивная пиксельная сетка**:
  * Визуализация дискретного растра с настраиваемым масштабом (Zoom $+/-$).
  * Перемещение рабочей области мышью (Pan/Drag).
  * Подсветка координатных осей $X$ и $Y$, подписи делений сетки.

* **Алгоритмы растеризации**:
  1. **Пошаговый алгоритм (Step Line)**: Базовое построение на основе прямого уравнения прямой $y = k \cdot x + b$.
  2. **Цифровой дифференциальный анализатор (DDA Line / ЦДА)**: Рекуррентное вычисление координат на базе приращений.
  3. **Алгоритм Брезенхема (Bresenham Line)**: Полностью целочисленная растеризация отрезков во всех 8 октантах.
  4. **Алгоритм Брезенхема для окружностей (Bresenham Circle)**: 8-симметричная генерация пикселей окружности.
  5. **Сглаживание линий по алгоритму Ву (Wu's Anti-aliasing Line)**: Генерация полутоновых пикселей с расчетом прозрачности (Alpha).
  6. **Алгоритм Кастла-Питвея (Castle-Piteway / Эллипс)**: Целочисленный алгоритм генерации эллипсов и дуг конических сечений.

* **Встроенный модуль бенчмарка**:
  * Стресс-тестирование производительности на **100 000 линий** и **50 000 окружностей**.
  * Оценка чистого времени выполнения без задержек отрисовки интерфейса.
  * Текстовый аналитический разбор результатов.

## 📐 Архитектура и математическое описание

### Архитектура приложения

1. **`IRasterTarget` / `VirtualGrid`**: Виртуальный растр, хранящий координаты $(x, y)$ и уровень интенсивности пикселей $[0.0, 1.0]$.
2. **`RasterEngine`**: Набор статических методов растеризации, принимающих координаты и виртуальный растр. Отделен от интерфейса.
3. **`App`**: Графическая оболочка на Tkinter, транслирующая пиксели `VirtualGrid` в прямоугольники `Canvas`.

### Алгоритмы растеризации

#### 1. Пошаговый алгоритм
Основан на решении уравнения $y = k x + b$. Шаг выбирается по оси с максимальным приращением $N = \max(|\Delta x|, |\Delta y|)$:
$$x_{k} = x_1 + k \cdot \frac{\Delta x}{N}, \quad y_{k} = y_1 + k \cdot \frac{\Delta y}{N}$$

#### 2. Цифровой дифференциальный анализатор (ЦДА)
Вычисление координат на основе шаговых приращений `x_inc = dx / steps` и `y_inc = dy / steps`:
$$x_{k+1} = x_k + \Delta x_{\text{inc}}, \quad y_{k+1} = y_k + \Delta y_{\text{inc}}$$

#### 3. Алгоритм Брезенхема (Линия)
Целочисленный алгоритм, использующий управляющую переменную ошибки $e$:
$$e = 2 \Delta y - \Delta x$$
Если $e < 0$, ошибка увеличивается на $2 \Delta y$. В противном случае ордината $y$ смещается на $1$, а ошибка изменяется на $2(\Delta y - \Delta x)$.

#### 4. Алгоритм Брезенхема (Окружность)
Строит окружность $x^2 + y^2 = R^2$ с начальным параметром ошибки $d = 3 - 2R$. Восьмикратная симметрия позволяет генерировать всю окружность на основе одного октанта:
$$(xc \pm x, yc \pm y), \quad (xc \pm y, yc \pm x)$$

#### 5. Алгоритм сглаживания Ву (Wu Anti-aliasing)
Рассчитывает интенсивность для двух соседних пикселей на каждом шаге генерации прямой в зависимости от дробной части точной координаты $y_{\text{exact}}$:
$$I(y_{\text{low}}) = 1.0 - \text{frac}(y_{\text{exact}}), \quad I(y_{\text{high}}) = \text{frac}(y_{\text{exact}})$$

#### 6. Алгоритм Кастла-Питвея (Эллипс)
Целочисленное построение дуги эллипса $b^2 x^2 + a^2 y^2 = a^2 b^2$ с использованием критерия принятия решений первой и второй областей (граничный уклона $m = -1$).

## ⚡ Бенчмарк производительности (Стресс-тест)

Результаты тестирования на генерацию массовых примитивов во всех 8 октантах:

| Примитив / Алгоритм | Количество | Время выполнения (сек) |
| :--- | :--- | :--- |
| **ЦДА (DDA Line)** | 100 000 линий | ~0.864 сек |
| **Брезенхем (Bresenham Line)** | 100 000 линий | **~0.441 сек** |
| **Брезенхем (Bresenham Circle)** | 50 000 окружностей | ~0.312 сек |
| **Сглаживание Ву (Wu Line)** | 100 000 линий | ~1.554 сек |

### 🔍 Почему Брезенхем быстрее ЦДА?
1. **Отсутствие операций с плавающей точкой**: ЦДА выполняет арифметику с типом `float` (`x_inc`, `y_inc`), требующую вычислений на блоке FPU. Алгоритм Брезенхема использует исключительно целочисленные сложения и побитовые сдвиги на ALU.
2. **Отсутствие функций округления**: Внутри основного цикла ЦДА на каждом шаге вызывается функция `round()`, приводящая к накладным расходам и сбросу конвейера процессора.
